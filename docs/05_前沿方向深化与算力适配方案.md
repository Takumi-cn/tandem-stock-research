# 前沿方向深化与算力适配方案

> 版本：v1.0 ｜ 日期：2026-10-25 ｜ 状态：规划完成（P3/P4/P5 执行蓝本）
> 输入：① 用户提供的前沿调研（六大问题域，2025–2026 前沿）；② ZCode 代码可得性核实；③ **硬约束：RTX 4060（8GB）本地运行 + 每日使用不能长时间占电脑**。

## 0. 摘要

前沿共识（用户调研收敛点）：**不再把非平稳性、状态切换、关系漂移当噪声去"消除"，而是当作一等公民显式建模**；评测从单一准确率转向 IC + 风险调整收益 + 解释质量 + 漂移鲁棒性。

本项目的落地裁决（两道门：**代码可得性** × **4060/10 分钟预算**）：

- ✅ **优先进入 P3/P5**（机制轻量、可自实现、有实证增益）：FactorMoE 式状态路由、TGNS 式概念-股票双重注意力 + WRL 损失、非平稳补偿模块（纯 PyTorch）、漂移检测 + 集成权重在线重校准；
- ✅ **降级使用**：TSFM（Kronos）→ 特征提取器 + 合成数据增强，不作直接预测器（D-13）；
- ⚠️ **WSL2 可选**：Mamba 系（mamba-ssm 官方仅支持 Linux，Windows 原生不可编译）；
- ❌ **明确不做**：LLM 的 GRPO/Time-GRPO 训练（4060 无法承担 7B 级 RL 训练）——只做推理时反思（SEP 式，D-14）。

## 2. 六大问题域 → 本项目落地方案

### 2.1 非平稳性：过平滑与滞后的显式补偿

**失败机制**：标准归一化（RevIN 等）把窗口均值/方差抹平，模型在"人工平稳化"的输入上预测，丢失趋势与局部突变 → 预测被拉向历史均值（过平滑）、突变后数步才跟上（滞后）。

**落地（P3，纯 PyTorch，零新依赖）**：
1. **自适应缩放/平移注意力**（NSC-Mamba ATA 思想）：归一化后让可学习的 scaling/shifting 因子参与注意力计算，把被抹掉的非平稳信号"找回来"；
2. **门控双分支融合**（GPFASS 思想）：短期突变分支（注意力）+ 长程分支（线性卷积/浅层 GRU 替代 SSM，**避开 Windows 下 mamba-ssm 编译问题**），门控自适应调节融合比例——波动期偏注意力、平稳期偏长程；
3. **专属诊断指标进看板**：过平滑比 = σ(预测)/σ(实际)；滞后阶数 = argmax(预测与实际的互相关)。这是"非平稳处理是否生效"的直接证据，不只看 IC。

**可选（WSL2）**：MambaStock/SAMBA 原生实现对照。

### 2.2 关系建模：动态概念-股票双重注意力 + WRL 损失

**失败机制**：静态图把"同一股票关联多个概念、概念驱动力随时变化"平均掉；多层 GNN 传播导致过平滑/过压缩。

**落地（P3）**：
- 图构建：申万/中金二级成分 = 预定义概念；节点 = 池内 20 只 + 扩池同行业成分（训练域，见 docs/03 §1.3）；
- **CGA（概念图注意力）**：概念-概念、概念-股票的时变关联权重；
- **SGA（股票图注意力）**：任意两股票间注意力，捕捉因子相关性解释不了的隐含互动；
- **WRL 加权鲁棒损失（D-17）**：对横截面收益做指数加权、优先拟合高收益端——把"预测精度"与"多空组合收益"在损失层就对齐；同时给 LightGBM 排序做对应的样本加权版作对照实验；
- 证据预期：TGNS 宣称 IC 较 PatchTST/HIST +12.3–21.9%（CSI100/300、NASDAQ-100），**本地门槛验证通过才采用**。

### 2.3 市场状态路由：FactorMoE 式（本项目最优先引入的前沿机制）

**失败机制**：公式化因子透明但静态加权无法适应市场结构切换；深度因子自适应但黑箱。

**落地（P3 先轻量版 → P5 完整版）**：
- **v1 轻量版（先行，因最轻且证据直接）**：门控输入 = 市场状态指标（指数波动率分位、指数 MA 斜率、风格因子近端表现）+ 各因子/各模型近 20 日 IC → softmax 门控权重动态组合因子分数与模型分数。**门控权重每日可读出 = 天然可解释**（"当前市场状态下模型给了动量多少权重"写进报告）；
- **v2（v1 验证有增益后）**：GRU 链式专家混合 + 多头注意力建模因子协同；
- 对齐证据（券商实证，用户提供）：GRU 八专家 MoE 将 RankIC 4.60%→6.10%，多头年化超额 9.79%→14.66%。

### 2.4 LLM 双路径：预测器与挖掘机严格分开

**预测器路径（P4 可选，默认关，D-14）**：
- SEP 式**推理时反思**：摘要→解释→预测→反思模块识别推理错误→修正。不做 GRPO/Time-GRPO 训练（算力不允许），效果上限低于论文（54.5%），定位为"集成的一路软信号 + 解释文本来源"；
- 本地方案：Qwen2.5-7B-Instruct int4（显存 ~5GB）；**只对集成最不确定的 top-5 股票运行**（约 3–5 分钟）；或走 API（费用开关）；
- VTA（推理链作为预测的显式中间变量）= 观察项。

**挖掘机路径（`--deep` 专属，预算 ≤2 小时）**：
- 三引擎按可得性选择：**RD-Agent（官方开源✅，微软）> LLM+MCTS 自实现**（回测表现作 MCTS 奖励 + 频繁子树回避防同质化）**> AlphaTree**（Tree-LSTM 结构先验，观察）；
- 产出永远先进沙盒验证（purged walk-forward + 门槛），通过才进 challenger 特征集。

### 2.5 TSFM 争议：把"宣称"与"证据"分开 → 降级定位（D-13）

- 正面宣称：Kronos 零样本波动率 MAE −9%、合成 K 线保真度 +22%；FinCast 宣称首个金融专用 TSFM 零样本能力。
- **反面证据（登记在案）**：2026 年约 5000 只中国股票实证——**Kronos 未跑赢简单波动率基准**（归因：BSQ 量化在重尾分布下失真、波动率推导方法论不匹配，且属架构默认不可调）；"通用 TSFM 是范畴错误"立场论文；预训练数据前视偏差风险；Kronos 团队自己也承认通用 TSFM 在金融上跑输领域专用架构。
- **落地**：Kronos-base（102M，显存 fp16 约 0.2–0.5GB）作 ①**表征提取器**（末层隐藏态降维后作为 L1 的特征）②**合成 K 线数据增强**（扩充稀有状态样本）；**不作为直接预测器参与投票**。Chronos-Bolt/Lag-Llama 保留零样本对照路（极轻量）。

### 2.6 在线持续适应：轻量化 RL-DAM（D-16）

- **DDD（动态漂移检测）**：每日运行 PSI（特征分布）+ ADWIN（残差异变），耗时 <1 秒；
- **三级适应动作**：一级 = 集成权重滚动重校准（每日、免训练）；二级 = 触发重训告警（写工作日志，建议 `--deep`）；三级 = 模型失效自动停报（既有机制）；
- 完整 RL-DAM 闭环（RL 策略调整）= 观察项，不实现。

## 3. 算力与时效预算（RTX 4060 适配总表）

### 3.1 逐模型测算（工程估算，P1 结束后用实测校准并写入工作日志）

> **✅ 2026-10-26 实测校准完成（RTX 4060 Laptop 8.6GB，torch 2.5.1+cu121）**：基准模型=2层Transformer d_model=64（67.7K参数）、batch=256、seq_len=60、20K样本、50 epoch、线程限2：
> - **GPU 训练 50 epoch = 41.6 秒**（估算"5–15分钟"过于保守，实际快约10倍）；
> - **GPU 单批推理 = 3.4ms**、峰值显存 **0.19GB**（"每模型≤2GB"约束余量巨大）；
> - CPU 对照（2线程）：50 epoch = 19.3 分钟、推理 74.7ms → **GPU 提速约 28×**；CPU 回退路径确认可行（应急用）。
> - 推论：P3 全部小模型（d_model 64–128）单个训练 1–5 分钟内完成，`--deep` 全链预计远低于 90 分钟上限；日常推理链毫秒级。FinBERT/本地LLM 项待 P4 安装后补测。

| 模型/组件 | 规模 | 显存 | 日常推理 | 训练（--deep） | 4060 结论 |
|---|---|---|---|---|---|
| L1 LightGBM | — | CPU | 毫秒级 | Optuna 50 trials 约 10–30 分钟（CPU） | ✅ 无压力 |
| L2 深度时序（iTransformer/PatchTST/TimeXer，d_model 64–128） | 0.1–1M 参数 | <1GB | 20 只股票 <1 秒 | 单模型 5–15 分钟 | ✅ |
| L2 HIST / TGNS 式图模型（池+扩池 100–300 节点，图很小） | <1M | <1GB | <1 秒 | 10–20 分钟 | ✅ 图小是天然优势 |
| L2c FactorMoE 式路由（GRU+8 专家） | 1–5M | <1GB | <1 秒 | 10–20 分钟 | ✅ 机制轻 |
| 非平稳补偿模块（§2.1） | 增量 <0.5M | <1GB | 忽略 | +2–5 分钟 | ✅ |

| RD-Agent / LLM+MCTS（因子挖掘） | 调 LLM | 视引擎 | 不入日常 | `--deep` 预算 ≤2 小时 + 调用上限 | ⚠️ 可选层 |

### 3.2 日常链路时间预算（目标 5–8 分钟，硬上限 10 分钟）

| 步骤 | 耗时 | 资源 | 电脑可用性 |
|---|---|---|---|
| 数据增量更新（QMT/akshare→baostock 降级） | 1–3 分钟 | 网络 IO | ✅ 可正常用电脑 |
| 质检 + 特征计算 | <1 分钟 | CPU | ✅ |
| 全部模型 forward + FinBERT 情绪 | 1–2 分钟 | GPU（短暂） | ✅ 基本无感 |
| （可选）本地 LLM top-5 反思 | 3–5 分钟 | GPU | ⚠️ 默认关 |
| 报告 + 台账 + 日志 | <1 分钟 | CPU | ✅ |
| **合计（关 LLM / 开 LLM）** | **约 3–5 / 6–9 分钟** | — | 达标 |

### 3.3 `--deep` 预算（每月，默认 ≤90 分钟）

LightGBM+Optuna（10–30 分钟 CPU）→ 深度模型重训 4–6 个小模型（30–60 分钟 GPU）→ Kronos LoRA（可选 20–40 分钟）→ 晋升评估与报告（<5 分钟）。可选因子挖掘引擎独立预算 ≤2 小时。提供 **`--night`**：注册凌晨 2 点任务，跑完自动休眠，完全不占白天。

### 3.4 超预算自动降级顺序（写入预算执行器）

1. 训练超时 → 跳过剩余 challenger，保留旧 champion 并告警；
2. 日常超时 → 先砍本地 LLM 层，再砍 Kronos 特征（标注"数据降级"）；
3. GPU 不可用（OOM/驱动异常）→ 小模型回退 CPU forward（秒–分钟级），Kronos/LLM 跳过并标注；系统**任何情况下都必须按时产出报告**（哪怕只有 L0/L1 路径）。

### 3.5 显存驻留策略

串行加载、即用即释放（每个模型 forward 完释放）；深度模型 fp16/bf16；本地 LLM 用 int4；同时驻留 ≤6GB，为桌面留 2GB 余量。

## 4. 评测标准 v2（吸收"收敛点"）

| 维度 | 指标 | 说明 |
|---|---|---|
| 预测力 | RankIC / ICIR / 方向准确率 | 原有体系不变（docs/01 §4.2） |
| 策略对齐 | top-k 模拟组合超额收益、Calmar/Sharpe | 回测含成本与涨跌停约束 |
| **解释质量（新增硬要求）** | 每个报告首页的 top 预测必须附：FactorMoE 门控权重快照 + SHAP top3 特征贡献 + 情绪一句话摘要 | **无解释的预测不得进入报告首页** |
| **漂移鲁棒性（新增）** | 滚动 60 日指标稳定性（标准差）、PSI 告警次数、停报触发记录 | 纳入月度复盘 |
| **非平稳诊断（新增）** | 过平滑比 σ(预测)/σ(实际)、滞后阶数 | §2.1 机制是否生效的直接证据 |
