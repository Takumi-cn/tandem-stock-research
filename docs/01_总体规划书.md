## ⚠️ 诚实性声明（必读，规划的前提）

在投入任何开发之前，必须先建立正确的预期，这决定了整个系统的设计哲学：

1. **股票明日涨跌无法被"精准"预测。** A股散户研究场景下，方向预测样本外准确率若能长期稳定在 **53%~58%**，就已经是具备真实统计优势的水平（学术界的顶会论文也大多在这个区间）。任何宣称 80%+ 准确率的方案，几乎必然存在数据泄漏或过拟合。
2. 因此本系统的目标不是"预测准确"，而是：**构建一套无泄漏、可验证、可复盘、可迭代的预测流水线**，让"是否真的有预测能力"这件事被诚实地度量出来，并随时间自动优化。
3. 所有预测结果**仅供个人研究学习，不构成投资建议**。系统在每份报告中都会强制附带本声明。

这个声明不是免责套话，它直接影响了下文的技术选型：我们宁可要一个"知道自己几斤几两"的 55% 系统，也不要一个回测 90%、实盘崩溃的过拟合系统。

## 0. 硬约束（v1.2 新增）：算力与时效预算

一切模型选型必须先过这道门槛，再谈精度（详细测算见 docs/05 §3）：

| 约束 | 预算 | 说明 |
|---|---|---|
| GPU | RTX 4060（8GB 显存） | 单模型显存 ≤2GB，同时驻留 ≤6GB，为桌面留余量 |
| 日常模式总时长 | **≤10 分钟（目标 5–8 分钟）** | 每交易日 17:30 运行，用户要正常使用电脑 |
| 日常 GPU 占用 | 仅 forward，≤2 分钟 | 日常链路禁止任何训练 |
| 深度优化 --deep | ≤90 分钟（默认） | 每月一次；提供 `--night` 凌晨自动执行、跑完休眠 |
| LLM 相关功能 | 默认关闭 | 本地 7B int4 或 API，均设调用数/时长上限 |

**架构铁律：训练与推理彻底分离**——日常链路 = 数据更新（网络 IO）+ 特征（CPU）+ 模型 forward（GPU 秒级）+ 报告；一切训练、调参、因子挖掘只在 `--deep`/夜间模式发生。超预算自动降级顺序见 docs/05 §3.4（任何情况下报告必须按时产出）。

## 1. 项目目标与范围

### 1.1 一句话目标

每个交易日（**周一至周五**，交易日历剔除法定节假日）收盘后（约 17:00–17:30）自动运行，输出**一份双标的每日预测报告**：

- **标的A（短线轨）**：从"中金财富客户端二级行业第一页"名单中挑选一只（用户指定，或系统对全名单评分推荐 Top1 并附完整排名）→ 预测 T+1 方向（涨/跌/震荡）、预期区间、置信度、多模型投票、入场/止损参考；
- **标的B（长线轨）**：中国铁物（000927）→ 明日方向预测（辅助信号）+ 长线仪表盘（趋势阶段/估值分位/距关键均线）+ 操作建议（加仓/持有/减仓/观察）与触发提醒。

周五的"明日"= 下周一。双轨详细设计见 docs/06。底层引擎（五层架构/模型阶梯/一键更新）保持本规划原设计，**交付层收窄为上述两标的**。

### 1.2 预测目标的形式化定义

| 项 | 定义 |
|---|---|
| 预测对象 | 股票池内每只股票（排除：停牌、ST/*ST、上市<60日新股、当日一字涨跌停无法交易者） |
| 预测目标 Y | T+1 收盘价相对 T 收盘价的涨跌幅 `ret(t+1) = close(t+1)/close(t) - 1`（前复权） |
| 主任务 | **截面排序**：预测池内股票明日涨幅的相对排名（谁强谁弱）——这是学术界与业界公认更可学的目标 |
| 副任务 | 方向分类：`sign(ret(t+1))`，三分类（涨>0.5% / 震荡±0.5% / 跌<-0.5%） |
| 输出 | 每只股票：方向概率 + 预期涨幅点估计与区间 + 置信度 + 各模型投票 |
| 约束 | 仅用 T 日收盘前可得信息（严禁未来函数），A股 T+1 制度 |

### 1.3 范围边界

- **做**：日频预测、收盘后批处理、次日走势；本地 Windows PC 运行；开源技术栈。
- **不做**：日内/分钟级交易信号、自动下单、融资融券/衍生品、实时行情流处理。

### 1.4 "二级行业第一页"的定义与歧义处理

调研与勘察结论（详见 docs/03 §1，v1.4）：用户**未注册账户**（免登录浏览行情），QMT/xtquant 通道**冻结**；用户截图（2026-10-25）确认：**免登录状态行情与二级行业页签完全可见**；客户端二级行业页签为 **881xxx 申万体系**（申万通道升级为基本同口径）；成分股默认按涨幅%降序。由此通道重排：

- **通道一（并列首选）**：akshare 申万二级（881xxx 同口径，P1 建立代码映射表核验）；
- **通道二（并列首选）**：只读解析 `D:\中金财富` 本地板块文件（通达信内核，作补充手段）；
- **通道三（保底）**：客户端界面手动复制名单导入。

"第一页"= 全成分排序后前 N 只的派生视图（支持涨幅降序/代码升序两种语义，config 切换）。行业推荐：**电池 881262（主）/ 半导体 881131（备）**（依据见 docs/06 §2.1a）。

> 待用户确认（已登记工作日志"待办"）：① 短线标的挑选方式（你指定一只 / 系统每日评分推荐 Top1）；② 行业确认（电池主推荐）；③ 每页行数 N（P1 实测）。

## 2. 总体架构（五层架构 + 双闭环）

```
┌────────────────────────────────────────────────────────────────────┐
│  L4 应用层    每日预测报告(MD/HTML)  准确率看板  工作日志自动追加      │
│              一键更新.bat  每日17:30计划任务  预测台账(ledger)         │
├────────────────────────────────────────────────────────────────────┤
│  L3 集成层    Stacking集成(动态加权)  置信度校准(isotonic)            │
│              多模型投票  涨跌停/停牌过滤  风险提示生成                 │
├────────────────────────────────────────────────────────────────────┤
│  L2 模型层    L0统计基线: 动量/均值回复/GARCH/ARIMA                   │
│              L1主力: LightGBM截面排序(Alpha158特征)                  │
│              L2深度: HIST概念图谱 + iTransformer/PatchTST/TimeXer    │
│              L3基础模型: Chronos/TimesFM/Lag-Llama 零样本+概率      │
│              L4增强: FinBERT中文情绪 + (可选)TradingAgents多智能体   │
├────────────────────────────────────────────────────────────────────┤
│  L1 特征层    量价特征(Alpha158子集+自研)  资金流  行业截面  情绪      │
│              滚动窗口特征库(parquet)  特征版本管理                    │
├────────────────────────────────────────────────────────────────────┤
│  L0 数据层    akshare(主) ⇄ baostock(备) 双源冗余自动切换             │
│              QMT股票池(申万近似) 日线/复权 财务 新闻 质检            │
└────────────────────────────────────────────────────────────────────┘
        ┌─────────────── 每日闭环 ───────────────┐
        │ 收盘→更新数据→生成特征→预测→报告→台账      │
        │ 次日收盘后自动核对昨日预测 vs 实际→准确率   │
        └───────────────────────────────────────┘
        ┌───────────── 持续优化闭环 ──────────────┐
        │ 滚动验证→challenger挑战champion→自动晋升  │
        │ Optuna调参 / RD-Agent挖因子(可选)         │
        │ 依赖升级隔离测试  漂移检测(PSI)告警        │
        └───────────────────────────────────────┘
```

设计原则：
1. **分层解耦**：数据/特征/模型/集成/应用各层独立版本化，任何一层可单独替换升级（这是"一键优化"的前提）。
2. **双闭环**：每日预测-复盘闭环（知道准不准）+ 持续优化闭环（不准了怎么办）。
3. **防御性设计**：数据源双冗余、模型注册表可回滚、所有自动动作写日志。

## 3. 模型分层策略（核心决策：为什么这样选）

**决策逻辑**：不是"用最炫的模型"，而是构建一个**从朴素到前沿的阶梯**，每一层都必须在滚动验证中证明自己比下一层有增量贡献，才被纳入集成。这是防止"高级模型负贡献"的关键机制。

| 层级 | 模型 | 来源/出处 | 角色 | 优先级 |
|---|---|---|---|---|
| L0 | 动量因子、均值回复、GARCH波动率、ARIMA | 经典统计 | 诚实基线+波动率估计（用于区间预测） | P2 必须 |
| L1 | LightGBM/XGBoost 截面排序 | 微软开源生态（Qlib Alpha158 特征库） | **主力模型**，性价比最高，CPU可跑 | P2 必须 |
| L2a | HIST 概念图谱图神经网络 | AAAI 2022 (Wentao-Xu/HIST)，Qlib模型动物园收录 | 利用"同行业/同概念股票联动"，**特别契合行业股票池场景** | P3 |
| L2b | iTransformer / PatchTST / TimeXer | ICLR 2024 / ICLR 2023 / NeurIPS 2024（thuml Time-Series-Library 统一实现） | 深度时序主力；TimeXer 支持外生变量（行业指数、资金流） | P3 |
| L2c | **FactorMoE 式状态路由**（GRU+门控专家，自实现） | 前沿机制（券商实证：RankIC 4.6%→6.1%，多头超额 9.79%→14.66%） | 以市场状态+因子近期表现为门控动态路由因子/模型组合；**门控权重可读出=天然可解释** | P3 优先 |
| L2d | **TGNS 式概念-股票双重注意力 + WRL 损失**（自实现，参考 TGN/RTGNN 开源） | 前沿机制（宣称 IC 较 PatchTST/HIST +12.3–21.9%，待本地验证） | 时变概念图+股票图注意力建模行业联动；WRL 损失对齐多空收益 | P3 |
| L2e | 非平稳补偿模块（ATA 式自适应缩放/平移 + 门控双分支，纯 PyTorch） | NSC-Mamba 思想移植（无官方代码，已核实） | 直接对冲过平滑与滞后；配专属诊断指标（过平滑比/滞后阶数） | P3 |
| L3 | Chronos-Bolt / Lag-Llama / **Kronos（金融K线基础模型，AAAI 2026，102M，官方开源）** | 开源时序基础模型 | **降级定位（D-13）：Kronos 作特征提取器+合成数据增强，不作直接零样本预测器**（约5000股反面实证已登记）；Lag-Llama 概率分布契合置信度区间 | P3 |
| L4a | FinBERT-tone-chinese 情绪 | HKUST（yiyanghkust/finbert-tone-chinese） | 新闻/公告/研报情绪特征化 | P4 |
| L4b | LLM 推理时反思（SEP 式；本地 Qwen 7B int4 或 API，可选） | SEP/TradingAgents 思路 | 集成软信号+解释文本来源；**不做 GRPO/Time-GRPO 训练**（4060 不允许，D-14）；仅对最不确定 top-5 运行 | P4 可选 |
| 集成 | Stacking + 概率校准 | 自研（约200行） | 最终输出，按滚动验证表现动态加权 | P5 |

**为何主力是 LightGBM 而非深度模型**：在日频、截面、小股票池（~20只×几年≈数千样本）的设定下，梯度提升树在学术界与 Qlib 官方基准中长期不弱于甚至优于深度模型，且训练快、可解释、不易过拟合。深度模型与基础模型的价值在于提供**与树模型相关性低的预测**，供集成层榨取增量。

**为何必须有 L0 基线**：如果整套深度学习系统的准确率跑不赢"5日动量"这种一行代码的规则，说明系统没有价值。L0 是所有后续投入的"性价比裁判"。

## 4. 验证方法论（决定成败的部分，最严格的一节）

### 4.1 防泄漏三原则

1. **Purged Walk-Forward CV（带禁运期的滚动前向验证）**：训练窗口滚动推进，训练集与验证集之间留 embargo（禁运期，建议 5 个交易日），清除标签重叠（用 t+5 备选标签做稳健性检验时尤其必要）。
2. **特征时间戳审计**：每个特征必须标注"信息可得的最早时刻"，财务数据按公告日对齐（而非报告期），资金流/情绪按当日收盘可得对齐。代码层用装饰器统一登记。
3. **复权与幸存者偏差**：全程前复权；股票池固化为历史快照，回测时用"当时在池内"的名单，不用"今天还活着"的名单。

### 4.2 评估指标体系

| 指标 | 定义 | 合格线 | 优秀线 |
|---|---|---|---|
| 方向准确率 | 三分类/二分类命中率 | >50%（有信号） | >55%（强） |
| RankIC | 预测排名与实际涨幅排名的秩相关（日均） | >0.03 | >0.08 |
| ICIR | IC均值/IC标准差 | >0.3 | >0.5 |
| Top-3 命中率 | 预测最强的3只平均涨幅 > 池内平均 的概率 | >55% | >65% |
| 模拟回测 | 含双边0.13%成本+涨跌停不可成交约束的top-k组合收益 | 跑赢随机选股 | 跑赢行业指数 |

### 4.3 复盘机制（每日闭环）

- `reports/predictions_ledger.csv`：每条预测（日期/代码/方向/概率/区间/实际/误差）永久留痕。
- 次日收盘后自动核对，滚动 20 日准确率写入看板；连续 20 日低于 48% 触发"模型失效告警"，自动降级为"仅观察模式"并在工作日志告警。

## 5. 分阶段实施计划（P0–P6）

> 每阶段有明确验收标准（DoD），未验收不进入下一阶段。总工期预估：全职投入约 2–3 周；间歇投入约 4–6 周。

### P0 调研与规划 ✅（本日完成）
- 已完成：开源生态调研（docs/02）、数据方案（docs/03）、一键更新设计（docs/04）、工作日志建立。
- **DoD**：用户审阅并确认本规划书，确认 §1.4 三个待确认事项。

### P1 环境与数据底座（预计 1–2 天）
- Python 3.11 venv + 依赖锁定（pinned requirements.txt，国内镜像源）。
- 双源数据管道：akshare 主 / baostock 备，自动切换、断点续传、完整性校验（缺日/停牌/复权核对）。
- 股票池获取：只读解析 `D:\中金财富` 本地板块文件获取中金二级成分（P1 验证格式，失败回退手动导入）→ `config/stock_pool.csv`；双标的配置 `config/targets.yaml`（短线标的 auto/指定 + 中国铁物 000927）。
- 拉取股票池 + 全市场日线（≥5年，前复权）、行业指数日线，落盘 parquet。
- **DoD**：一键拉齐全部历史数据并通过质检脚本（无缺日、复权连续、池快照留痕）。

### P2 特征工程与基线（预计 2–3 天）
- Alpha158 特征子集移植（Qlib 语法参考，自行实现避免重依赖）+ 自研 A 股特色特征（换手率变化、量价背离、涨停距离、行业相对强弱、资金流累计）。
- L0 统计基线 + L1 LightGBM 排序模型 + purged walk-forward 评估框架。
- 回测引擎（简版：top-k 等权、成本与涨跌停约束）。
- **DoD**：产出第一份诚实的滚动验证报告：L1 相对 L0 有可解释的增量（RankIC、准确率），否则先修特征不加上模型。

### P3 高级模型（预计 4–6 天，优先级按 docs/05 §5）
- ① FactorMoE 式轻量状态路由（最轻、证据直接，先行验证）；
- ② TGNS 式概念-股票双重注意力 + WRL 损失（行业池场景最契合）；
- ③ 非平稳补偿模块（纯 PyTorch：ATA 式缩放/平移 + 门控双分支）+ 过平滑/滞后诊断指标；
- ④ Kronos-base 特征提取器接入（102M，显存 <0.5GB）；
- ⑤ thuml Time-Series-Library 的 iTransformer/PatchTST/TimeXer（统一接口）+ HIST 概念图谱；
- ⑥（WSL2 可选）MambaStock/SAMBA 对照（mamba-ssm 不支持 Windows 原生）。
- **DoD**：每个新模型与 L1 的预测相关性 <0.9（集成多样性）且单独验证不弱于 L0；单模型训练时长 ≤20 分钟（4060）；否则不进集成。

### P4 情绪与 LLM 增强（预计 2–4 天，可拆分延期）
- akshare 个股新闻/公告/龙虎榜抓取 → FinBERT-tone-chinese 情绪打分 → 滚动情绪特征进 L1（GPU 约 5 秒/日）。
- （可选，默认关）SEP 式推理时反思：本地 Qwen2.5-7B int4（约 5GB 显存）或 API，**仅对集成最不确定的 top-5 股票**运行（3–5 分钟），输出软信号+解释文本；VTA/Time-GRPO 列为观察项不实现。
- **DoD**：情绪特征使 L1 滚动验证指标稳定提升；LLM 层有硬预算上限且超时自动跳过；日常总时长仍 ≤10 分钟。

### P5 集成与报告（预计 2–3 天）
- Stacking 集成 + isotonic 概率校准 + 动态权重（近 60 日滚动表现）。
- 每日报告生成（Markdown + HTML 看板）：预测表、多模型投票、置信度、风险提示、免责声明、昨日复盘。
- **DoD**：集成验证指标 ≥ 单模型最优；报告自动生成且含复盘。

### P6 一键更新与自动化（预计 1–2 天，详细设计见 docs/04）
- `一键更新.bat` / `安装环境.bat` / `注册每日任务.bat` 三件套。
- Model Registry（champion/challenger 自动晋升与回滚）。
- 预测台账 + 准确率看板 + 工作日志自动追加。
- **DoD**：双击 bat 即完成"数据→预测→报告→复盘"全链；模拟一次模型自动晋升与一次故障回滚。

### 持续运营（上线后）
- 每交易日 17:30 自动运行（Windows 计划任务）。
- 每月一次深度复盘：特征再筛选、Optuna 调参、（可选）RD-Agent 因子挖掘，全部由 `一键更新.bat --deep` 触发。

## 8. 技术栈总览

| 类别 | 选型 | 备注 |
|---|---|---|
| 语言/环境 | Python 3.11 + venv，Windows 计划任务 | 用户本机 |
| 数据 | akshare（主）+ baostock（备），parquet 存储 | 双源冗余 |
| ML | LightGBM、scikit-learn、Optuna | 主力与调参 |
| 深度时序 | PyTorch + Time-Series-Library（iTransformer/PatchTST/TimeXer） | 参考 thuml 开源实现 |

| 基础模型 | Chronos-Bolt / TimesFM / Lag-Llama（Mila，HuggingFace 权重） | 零样本+概率区间 |

| 可选 LLM | TradingAgents 框架思路 + 任意 LLM API | 多智能体软信号 |
| 报告 | Markdown + HTML（无外部依赖模板） | 本地看板 |

> 注：Qlib 与 FinRL 的定位说明见 docs/02 §5——结论是**借鉴其方法论（Alpha158特征、评估协议、HIST模型），不整体引入框架**，以降低 Windows 部署复杂度；RD-Agent 作为可选的"一键挖因子"增强通道。

## 9. 本规划的"详细思考"遗留问题（开放项）
