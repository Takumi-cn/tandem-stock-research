# 一键更新与持续优化设计（"一键完善优化更新"功能）

> 版本：v1.0 ｜ 日期：2026-10-25 ｜ 状态：设计完成，待 P6 实现
> 设计目标：**用户双击一个 bat，系统自己变强**。日常零操作，优化全自动，出事能自愈，全程留痕。

---

## 1. 总体设计：一个入口，三档模式

```
双击 一键更新.bat
   │
   ├── 默认模式（每日，约3-8分钟，全自动无人工）
   │     更新数据 → 质检 → 生成特征 → champion预测 → 集成 → 出报告
   │     → 核对昨日预测(复盘) → 写台账 → 追加工作日志 → 自检
   │
   ├── --deep 深度优化模式（每月/手动，约30-120分钟）
   │     在默认模式之上：
   │     ① 重训全部 challenger 模型（滚动前向验证）
   │     ② challenger 胜过 champion → 自动晋升（可回滚）
   │     ③ Optuna 超参搜索（预算可设）
   │     ④ 特征再筛选（剔除失效特征，PSI漂移检测）
   │     ⑤ （可选 --rd-agent）RD-Agent 自动挖掘新因子
   │     ⑥ 生成月度复盘报告
   │
   └── --upgrade 升级模式（季度/手动）
        ① 隔离venv中安装新版依赖 → 跑回归测试集
        ② 通过 → 切换并锁定新版本；失败 → 保持旧版并告警
        ③ 拉取上游开源仓库新版本号提示（Qlib/TSLib/Chronos等）
```

### 运行预算（RTX 4060 硬约束，详细测算见 docs/05 §3）

| 模式 | 频率 | 总时长 | GPU 占用 | 电脑可用性 |
|---|---|---|---|---|
| 日常 | 每交易日 17:30 | **5–8 分钟（硬上限 10 分钟）** | 仅 forward，≤2 分钟 | 数据阶段可正常使用电脑 |
| --deep | 每月/手动 | 默认 ≤90 分钟 | 训练 30–60 分钟 | 建议休息时跑，或用 --night |
| --deep --night | 每月凌晨 2 点 | 同上，完成后自动休眠 | 同上 | 完全不占白天 |
| --deep --rd-agent / 因子挖掘 | 手动 | ≤2 小时（独立预算，可中断续跑） | 视引擎 | 夜间 |
| --upgrade | 季度 | ≤30 分钟 | 回归测试 | 可正常使用 |

预算写入 `settings.yaml`（`budgets.*`），由**预算执行器**强制执行，超时自动降级（docs/05 §3.4）：训练超时→保留旧 champion 并告警；日常超时→先砍本地 LLM 层再砍 Kronos 特征；GPU 异常→小模型回退 CPU。**任何情况下报告必须按时产出。**

## 2. 脚本三件套（scripts/）

### 2.1 `安装环境.bat`（一次性）
- 检测 Python 3.11 → 创建 `.venv` → 清华/阿里镜像源安装 pinned `requirements.txt` → 冒烟测试（拉1只股票3天数据+跑一个L0基线）→ 输出绿色成功清单。
- 幂等设计：重复运行只补缺不重装。

### 2.2 `一键更新.bat`（日常入口，对应 `一键更新.py`）
```
用法：
  一键更新.bat                 日常模式（每日预测+复盘）
  一键更新.bat --deep          深度优化（重训+晋升+调参）
  一键更新.bat --deep --night  凌晨2点自动深度优化，完成后休眠（不占白天电脑）
  一键更新.bat --deep --rd-agent  加入LLM自动因子挖掘（需API Key）
  一键更新.bat --upgrade       升级依赖（隔离测试后切换）
  一键更新.bat --rollback M-x  回滚到指定模型版本
  一键更新.bat --status        查看当前champion/台账/准确率摘要
```
- 控制台彩色分步输出（每步 ✓/✗ 与耗时），任何一步失败：自动重试→降级→明确红字告警，**绝不静默失败**。
- 全程 tee 到 `reports/runs/run_YYYYMMDD_HHMM.log`，摘要自动追加到 `工作日志.md`（格式见工作日志"自动日志区"）。

### 2.3 `注册每日任务.bat`
- `schtasks` 注册每个交易日 17:30 运行日常模式（周末自然无数据，脚本自判交易日）。
- 附 `取消每日任务.bat`。

## 3. 持续优化机制细节

### 3.1 Model Registry（champion/challenger 自动晋升与回滚）

`models/registry.json` 记录每个模型每个版本的：训练窗口、验证指标（准确率/RankIC/ICIR）、入集成权重、晋升历史。

**晋升规则（保守，防抖动）**：
1. challenger 在最近 60 交易日滚动前向验证中，RankIC 与准确率**同时**优于 champion，且优势超过 2 个标准误；
2. 连续两周每日复盘不劣于 champion；
3. 满足后才晋升，旧 champion 保留为影子模型并行运行 20 日（安全网），`--rollback` 一键恢复。

### 3.2 Optuna 自动调参（--deep 触发）
- 搜索空间：LightGBM（叶子数/学习率/特征采样等）、深度模型（hidden/层数/patch长度）、集成层权重。
- 预算控制：`settings.yaml` 中 `tuning.n_trials`（默认 50，可调）；TPESampler，以滚动验证 RankIC 为目标。
- 结果写入 `models/tuning/`，最优参数自动进入下一轮 challenger。

### 3.3 特征健康度管理
- 每月计算每个特征的 **PSI（群体稳定性指数）**：PSI>0.25 的特征标记"漂移"，自动降权并写入工作日志；
- 特征重要性连续 3 个月垫底（累计<1%增益）→ 自动移出候选池，`--deep` 时重新评估可回归。

### 3.4 RD-Agent 因子挖掘（可选，D-07）
- `--deep --rd-agent` 时调用 microsoft/RD-Agent（需 LLM API Key，费用自负）：
  输入=当前特征库+数据接口说明，输出=新因子代码 → 自动进入"沙盒验证"（同样的 purged walk-forward + 门槛）→ 通过才进 challenger 特征集。
- **隔离原则**：RD-Agent 产出永远先进沙盒，不直接上线。

### 3.5 依赖与模型升级通道（--upgrade）
- 新依赖先进 `.venv_upgrade` 隔离环境 → 运行回归测试（固定的小样本数据集+期望指标区间）→ 通过则切换，失败则告警不切换；
- 上游仓库（Time-Series-Library/Chronos/HIST 等）发版检测：仅提示+评估报告，不自动升（大版本行为变化需人工确认，写入工作日志待办）。

### 3.6 数据源自愈
- akshare 单接口失败：自动切换 baostock 同义接口；两者皆失败：重试3次（指数退避）→ 跳过该数据族并在报告标注"数据降级"；
- 连续 2 日数据不完整 → 工作日志红字告警 + 暂停深度优化（防止脏数据训练）。

## 4. 复盘与看板（让"变强"可见）

- `reports/predictions_ledger.csv`：每日每股票一行（预测方向/概率/区间/实际/误差/命中与否），只追加不修改。
- `reports/dashboard.html`（纯本地静态页，无外部依赖）：
  - 滚动 20/60 日方向准确率曲线（对照 50% 虚线与 L0 基线实线）；
  - 各模型单独 vs 集成的近期表现对比条形图；
  - 模型版本时间线（何时晋升/回滚）；
  - 数据质量与漂移告警区。
- **自动停报机制**：滚动 20 日准确率 <48% → 报告顶部红字"模型失效观察期"，预测仅供参考，同时触发工作日志告警与一次 --deep 建议。

## 5. 安全边界

1. 所有自动优化仅动**模型与特征**，不改股票池（池变更=人工快照，见 docs/03）；
2. 所有自动动作（晋升/回滚/降权/停报）必须留痕工作日志，格式固定可追溯；
3. LLM 相关功能（RD-Agent/TradingAgents）默认关闭，显式开关+费用提示后才启用；
4. 任何删除类操作（清理旧模型版本）保留最近 5 个版本，超出才清理。

## 6. 验收标准（P6 DoD）

- [ ] 全新机器：`安装环境.bat`→`一键更新.bat` 两步出当日报告；
- [ ] 模拟 challenger 更优：自动晋升且报告与日志留痕；
- [ ] 模拟晋升后失效：影子机制触发回滚；
- [ ] 断网/接口挂：数据降级流程走通且报告标注；
- [ ] 计划任务连续 3 个交易日自动运行成功。
